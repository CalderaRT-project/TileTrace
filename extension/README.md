# TileTrace

通过静态 Python AST 分析 Triton kernel 的逻辑形状和变换，界面不执行用户源码或 kernel，不显示实际张量数值。采用 MIT 许可证（见仓库根目录 LICENSE）。

## 安装与快速开始

在 VS Code 扩展面板的菜单中选择 **Install from VSIX…**，安装 `tiletrace-0.1.5.vsix`。从源码构建方法见下方“从源码开发与打包”。运行时需要 Python 3.10+，无需安装 Triton、NumPy 或使用 GPU。

在工作区中打开带 `@triton.jit` 的已保存 `.py` 文件，再点击编辑器右上角独立的 **TileTrace 矩阵图标**，或运行命令 **TileTrace: 打开变换可视化**，手动打开右侧中文面板。打开、切换或拆分源文件均不会自动创建或调出面板；面板已打开时仍跟随当前源码更新，关闭后需要再次手动打开。工具栏按钮和面板标签使用深浅主题图标，与 VS Code 的拆分编辑器按钮分开。支持常见 `import triton as ...`、`from triton import jit as ...` 装饰器别名；复杂导入形式可能需要改用常见形式。切到普通 Python 文件时清除已显示的分析，面板获得焦点时保留对应源码编辑器。

选择 kernel 后即可使用已有默认参数查看。缺少参数时，在“分析参数”中补充 JSON：例如 constexpr `{"BLOCK":8}`、输入形状 `{"x":[2,4]}` 和 program ID `[0]`；输入形状是可选静态信息。查看操作列表、上一步/下一步、代码表达式、输入和输出形状，点击输出格子查询直接输入的来源坐标。选中源码表达式也会同步选中的操作；查看源码按钮跳转至原文件。网格代表逻辑坐标，不代表 GPU 线程、全局内存地址或实际数据值。

仓库提供 `examples/flash_attention.py`：一个 program 处理 16 个 Q 行，循环读取 K/V 分块，展示转置、矩阵乘法、在线 softmax 和输出归一化，默认参数无需手填。

## 可视化与交互

面板顶部显示文件名、当前操作和源码行号。输出网格优先显示，来源摘要位于网格下方。窄面板可展开“步骤列表”，宽面板在左侧展示步骤。循环内的步骤按迭代分组，源码选择变化时会把当前项滚入列表可见区。

默认列表显示关键张量步骤，折叠常量、参数和纯标量索引准备。勾选“显示全部节点”恢复完整列表，前后导航跟随当前视图。`arange` 的起点、终点、长度显示在“参数与属性”中。张量归约产生的标量及其后续计算作为步骤和数据输入显示。

当 `arange` 的索引参与可静态推导的 `tl.load` 地址时，“分块位置”会用小图展示逻辑读取区间、program 或循环偏移与可识别的掩码上界。选中 `arange` 或读取步骤的坐标，可在网格下方查看换算后的逻辑坐标。可通过“分析参数”里的 `program_ids` 切换 program。

普通视图中，长度超过 8 的轴默认显示首尾各 3 项，中间以可点击省略号表示。“展开显示窗口”后每张卡片最多显示 128 个坐标，超出范围可用轴起点浏览。rank > 2 使用前缀轴切片，最后两个轴作为网格轴。二维网格通过行列头标记坐标，选中的输出格显示行列索引。形状、方向与数量可通过悬停提示查看。

面板默认打开“简约”视图，每卡直接显示最多 4 行 × 4 列真实坐标，较短的轴按实际长度显示。点击输出格即可查询来源。通过“行起点”“列起点”移动窗口，卡片显示完整 shape。用网格上方的“简约 / 普通”切换视图，两种视图各自记住窗口位置。

展开“坐标明细”可查看返回与总计数量、枚举截断说明和坐标列表。点击“定位首个来源坐标”会将输入窗口移到对应位置。编辑源码或改变参数期间会清除网格与旧映射。

按钮、下拉框、JSON 输入与轴切片支持键盘操作，并使用 VS Code 主题与焦点颜色。查看诊断可以区分缺少参数、形状不兼容和分析能力限制。无 kernel 节点时显示诊断与补充参数提示。

同一文件的重绘保留页面与内部列表/网格滚动、参数区展开状态、焦点及 JSON 输入光标位置。等待新分析的短页面不会覆盖完整视图的阅读位置；新文件使用自己的阅读位置，首次打开从顶部开始。页面内容减少时，滚动位置受浏览器新的范围限制。关闭并重新创建面板后阅读位置重新初始化。

## Python 分析进程

VSIX 内置使用 Python 3.10+ 标准库的分析进程。仅在 VS Code 已信任的工作区启动分析；配置的 Python 可执行文件及工作区 `.venv` 也必须可信。

`tiletrace.pythonPath` 默认为 `python`。扩展会先检查当前文件所属工作区的 `.venv`，再从 `PATH` 查找 `python3` 或 `python`，并验证解释器能运行且版本达到 3.10。也可直接填入 Python 可执行文件的绝对路径。

扩展通过一个本地 Python 进程处理分析与坐标查询，分析状态保存在内存中。切换到多根工作区的另一个文件夹时，扩展会重新启动进程，并按默认设置查找新文件夹中的 `.venv`。进程使用 JSON Lines，stderr 写入 **TileTrace** 输出通道。请求约 15 秒超时会终止进程，下一次请求重新启动。也可运行 **TileTrace: 重启分析进程** 主动重启。Python 找不到时检查该输出通道并配置可执行路径。

进程以 `-I -S` 隔离模式从扩展自带的 Python 目录启动，通过固定的扩展代码加载明确的后端目录；开发时使用此工具仓库中的后端。源码工作区不进入当前目录或导入搜索路径，`PYTHONPATH`、`PYTHONHOME`、用户 site 和 site 启动脚本不影响 worker。用户源码仅作为 JSON 字符串交给静态分析器。

## 从源码开发与打包

在仓库根目录运行以下命令。

```sh
npm --prefix extension ci
npm --prefix extension test
npm --prefix extension run package
```

`package` 会编译 TypeScript，将根目录 `tiletrace/*.py` 复制到生成的 `extension/python/tiletrace/`，输出 `dist/tiletrace-0.1.5.vsix`。请从完整仓库构建。

开发前先在 `extension/` 安装开发依赖。扩展宿主调试配置由开发者保存在本机 `.vscode/` 中，该目录不纳入版本控制。扩展开发宿主中打开 `examples/` 的 Triton 文件。通过 VS Code 扩展面板的 **Install from VSIX…** 手动安装生成的包。

自动验证包含节点选择、版本和请求代次保护、真实子进程的通信与超时恢复，以及 jsdom 中的输出点击、来源高亮、高维切片、符号状态和巨型网格限制。
